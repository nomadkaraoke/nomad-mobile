# Store screenshots

The App Store / Play listing's hero screens, generated by one re-runnable pipeline. **Any files here are
placeholders until the Phase 7 UX polish lands: regenerate before submitting the listing.**

## Regenerate

```
scripts/store-screenshots.sh                        # iphone-6.9, ipad-13, android; locale en
scripts/store-screenshots.sh --locale de            # another app language
scripts/store-screenshots.sh --devices iphone-6.9   # a subset
scripts/store-screenshots.sh --check-only           # only verify/fix the sizes of existing files
```

It runs `maestro/screens/store-tour.yaml` through `scripts/e2e-local.sh --screen store-tour` per device and
writes `docs/store/screenshots/<device>/<locale>/store-01-discover.png` ... `store-06-me.png`:
Discover picks with a fit badge, song page (fit card, versions), Make (a job needing you + a ready one),
native lyrics review, Tonight at the fixture night with a song queued, Me's music profile with the voice
section. After a UI change, update the tour's testIDs if a screen moved, then re-run.

Prerequisites: the dev client installed on each device, the gen / decide / kjbox local stacks (see CLAUDE.md,
E2E; the tour needs decide with the vocal range fixtures and `../kjbox` for Tonight), an iOS 26 SDK
(the script creates the "iPhone 17 Pro Max" and "iPad Pro 13-inch (M5)" simulators if missing) and a running
Pixel AVD (`ANDROID_SERIAL`, default `emulator-5554`). Devices are shared: the script refuses to start while
another Maestro process runs (its iOS driver port 7001 is global).

## Required sizes (portrait)

| Store | Device | Size |
|---|---|---|
| App Store | iPhone 6.9" | 1320 x 2868 or 1290 x 2796 |
| App Store | iPad 13" | 2064 x 2752 (2048 x 2732 also accepted) |
| Google Play | Phone | short side >= 1080 px, long side <= 2x short side |

The script prints each folder's size and, only when a shot is off, resizes/pads it with `sips` (macOS).
Prefer fixing the simulator/AVD to the right device over relying on padding.
