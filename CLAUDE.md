# Claude Code Instructions for Nomad Mobile

The combined Nomad Karaoke iOS/Android app: one app for every Nomad Karaoke project (decide recommendations, gen karaoke videos, kjbox nights, a singer's own history). **Read [docs/VISION.md](docs/VISION.md) first**: it has the four use cases, the navigation, the release bar (no publishing until all four have a first usable version) and the phase roadmap.

**Status:** Phase 1 "Make it" (2026-10-17): real gen sign-in → make → pay → watch, verified by nine Maestro flows on iOS and Android against the gen local stack, plus a prod check of the release APK (real email-code sign-in, live Stripe checkout open/cancel, real audio search). Phase 1b "Search parity" (2026-10-19) then rebuilt song search on decide's search service: offline song list, outcomes (did-you-mean, resolve, versions, pick screen), make-flow match judge, flows search-1…4 + make-10. Phase 2 "Native review" (2026-10-20) is built: lyrics review (line list, issues bar, word/edit/nudge sheets, Tap To Sync, vocal-gap callouts) and Finish (A/B instrumental chooser, preview, three-call submit) run natively, replacing the web bridge; its prod check is pending. Phase 3a "Discover core" (2026-10-21) is built: sign-in card, 4-step taste quiz, personalised recommendations from decide (sections, Love / Not for me, offline last picks), the filter bar and sheets, the KaraFun / community library filter (also on search), and Me's music profile; decide accepts the gen session token directly. Apple Music connect (2026-10-22) is in ahead of 3b: Me → Your music profile → Connect Apple Music opens decide web's MusicKit JS page (`/connect/apple-music`) in the phone's browser (not an in-app tab: custom tabs drop Apple's popup opener) with a one-time link from `POST /api/services/apple-music/link`; decide reads the library and recent plays, and the page hands back to `nomadkaraoke://music-connected` (`+native-intent.tsx` keeps the screen). Phase 3b "Music data" (2026-10-23) is built: Me or Improve → Connect your music hub (`discover/connect/`) adds music from a screenshot (Gemini, via decide), playlist links (Spotify embed, best-effort and capped at 50 tracks, and YouTube Music), a Spotify export parsed on the phone (only aggregates go up) with an offline upload queue and local reminders, Apple Music (MusicKit connect, with the privacy export as a fallback link), ListenBrainz (one-tap OAuth or username, upload of the Spotify zip to ListenBrainz, daily lb-poll job on decide) and Last.fm. On Android, Share → Nomad Karaoke opens the import screen (`modules/share-intake`). Maestro connect-1…5 against the decide local stack with `DECIDE_FAKE_EXTERNALS` pass 5/5 on iOS and Android. Full-suite regression 2026-10-23: iOS 37/39, Android 38/39. review-12 needs gen web on :3010. review-10 fails on iOS at select-line line 3, which is pre-existing on main. Phase 3c "Vocal range" (2026-10-23) is built: Discover's Improve card and Me → Your music profile → Your voice open a mic test (`discover/voice`: low note, high note, a free sing (30 s, started by "I'm ready" so the singer can think of a song first), on-device pitch detection, a keyboard strip of the measured range, a likely voice type and a confidence line) or a self-report (voice type, or lower / middle / higher voice when not sure); the profile saves on the phone first and syncs to decide's `/api/my/voice` (an offline queue, reconciled app-wide), and recommendations v2 add fit badges ("Fits your voice", "Try it 2 keys down", "Fits an octave down"), the Singable filter (`singable` / `sort=fit`) and a range tier plus fit card on the song page. decide PRs #178, #180, #181, #185 (song vocal range data from UltraStar, note data and a Gemini batch; prod catalog.db has `vr_*` at 73.5% coverage). Phase 3d "Voice session" (2026-10-25) is built behind decide's `VOICE_SESSION_OPEN` flag (admins only until Andrew's tuning, G1): Discover's Improve card or Me → "Find your voice" opens a guided session (`discover/voice-session`: intro, setup with posture / warm / record / headphones, warm-up, pick a song you know from decide's analysed pool, play a community karaoke version in our own YouTube IFrame-API page (react-native-webview, baseUrl https://nomadkaraoke.com, else Error 153) or link out with a local reminder, optional recording (AAC, uploaded through a persisted queue, private, deletable from Me), a short quiz pre-filled from on-device pitch, and decide's adaptive next-song choice until Finish gives a voice type with a confidence line); the result saves as method `session`. `src/media/youtube.ts` is the app's single YouTube path. ## Stack

| Layer | Choice |
|---|---|
| Framework | Expo SDK 57 (`expo@~57.0.29`, RN 0.86, React 19.2, Hermes v1, New Arch), dev-client builds (not Expo Go) |
| Routing | Expo Router, typed routes. Routes live in `apps/mobile/src/app/` |
| Server state | TanStack Query 5 |
| Client state | Zustand 5; session in `expo-secure-store` |
| API clients | `@hey-api/openapi-ts` 0.99 (pinned) generated from committed OpenAPI snapshots |
| i18n | `use-intl` + `expo-localization`, 33 locales, English fallback |
| Styling | Uniwind (Tailwind v4); tokens mirror gen web |
| Lists / graphics | FlashList and Skia, **only through `@nomad/ui` wrappers** |
| Tests | jest-expo + @testing-library/react-native 13; Maestro E2E |
| Observability | Sentry + PostHog SDKs, inert until `EXPO_PUBLIC_SENTRY_DSN` / `EXPO_PUBLIC_POSTHOG_KEY` are set |

## E2E (Maestro against the gen, decide and kjbox local stacks)

- **Run suites in CI, not on Andrew's Mac** ([docs/TESTING.md](docs/TESTING.md); the build host: the private workspace `../docs/BUILD-HOST.md`): push, then `scripts/e2e-ci.sh run` (full suite, iOS + Android, sharded over the self-hosted Mac's 3 lanes, or GitHub-hosted with `--hosted`, each shard with its own stacks; `--platforms`, `--filter`, `--affected`, `--gen-ref …`), or `scripts/e2e-ci.sh pr` for the PR's own run (PRs run only the flows their changes affect; label `e2e-full` runs all). Results and failure screenshots land in `.e2e-ci/<run id>/`. Locally, run only the flow you are writing; `e2e-local.sh` queues on a device lock (`scripts/device-lock.sh status`), so parallel sessions wait instead of breaking each other.

- **Stack:** gen's `scripts/local-stack.sh` (real FastAPI on the Firestore/GCS emulators, `FAKE_WORKERS=1`; gen `docs/TESTING.md` § Local stack). API `http://127.0.0.1:8010`, web `:3010`, `LOCAL_STACK_API_URL=http://127.0.0.1:8010`. `scripts/e2e-local.sh` starts it from `GEN_DIR` (default `../karaoke-gen`, the main clone; needs gen ≥ v0.278.2. To test unmerged gen code, `GEN_DIR=../karaoke-gen-<worktree> scripts/e2e-local.sh …`, or run `scripts/local-stack.sh up --frontend` there yourself with `LOCAL_STACK_API_URL=http://127.0.0.1:8010`) when it isn't up.
- **Decide main API stack (Phase 3a):** decide's `scripts/local-stack.sh up` runs the main API on **:8030** plus the search service on :8020, both on gen's Firestore emulator (`FIRESTORE_EMULATOR_HOST=127.0.0.1:8080`), so gen sessions made by gen's local stack validate in decide. `EXPO_PUBLIC_DECIDE_API_URL` is the main API (:8030), `EXPO_PUBLIC_DECIDE_SEARCH_URL` the search service (:8020; defaults to the decide API URL when unset, as in prod). `scripts/e2e-local.sh` starts it from `DECIDE_DIR` when either port isn't ready and checks `/api/test` is mounted (`DECIDE_TEST_API=1`). The local stack has no BigQuery; decide answers smart artist suggestions and artist search (quiz step 3) from its catalog.db there (decide ≥ the artist-affinity branch's catalog fallback), so discover-2 loves the first suggestion and asserts that artist's songs in "Songs you know" or "From artists you love" (decide seeds a quiz artist's top 5 songs as known).
- **Discover flows (discover-1…6, Phase 3a):** `stack.js` `ACTION: decide-seed` (`PROFILE` JSON: genres, decades, energy, artists with affinity, loved/hidden song keys) and `decide-reset` write the user's decide profile through decide's `/api/test/profile/*` (`DECIDE_STACK`, default :8030); `common/discover-seeded.yaml` seeds, signs in from the Discover card and waits for the picks. Picks rows are matched by their accessibility text ("title, artist, reason, badges"); to tell whether a filter changed the songs, compare the row's menu button (`rec-menu-…`, labelled "More options for <title>") instead, since a row's own text also changes when the same song gains a badge. `scripts/remember-text.js` keeps a `copyTextFrom` result regex-escaped (`FIRST_PART=1`: only the text before the first comma, e.g. a quiz tile's artist name). The library and recommendation filters persist on the phone (iOS keeps app data between flows), so flows that change them reset them in `onFlowComplete` (`common/discover-reset-filters.yaml`). discover-6a (tagged `offline-warmup`) loads a user's picks and runs right before the `force-offline` group (after the Hebrew group, which clears or signs out); discover-6b relaunches keeping the app's data (`common/relaunch-keep-data.yaml`) and asserts the offline picks. Shots in `${DISCOVER_SHOTS}` = `docs/screenshots/phase3a/<platform>/`; the Discover screen tour (`--screen discover-tour`) goes to `docs/screenshots/phase3a/<platform>/<locale>/`.
- **Voice flows (voice-1…3, Phase 3c):** Metro bundles with `EXPO_PUBLIC_FAKE_MIC=baritone-scale` (`e2e-local.sh` sets it; `config.ts` honours it only against a local gen host): the voice test plays `assets/fake-mic/baritone-scale.wav` (low / high / sing slices, `scripts/make-fake-mic-wav.mjs`) instead of the mic. voice-1 holds a few seconds after Done enables (the slice slides down to A2), so the result is "Likely Baritone"; voice-2 self-reports Tenor; voice-3 seeds a baritone self-report (`stack.js ACTION: voice-seed`, `PROFILE` = decide's `VoiceProfileIn`, `measured_at` defaults to now) plus a Muse + Adele persona, and on decide's fixture `vr_*` data Muse "Starlight" fits, "Uprising" is "Try it 2 keys down" and Adele "Hello" is outside (no badge, hidden by Singable). `ACTION: voice-assert` (`EXPECT_TYPE`, `EXPECT_METHOD`) polls decide's `GET /api/test/profile` `voice_profile`. iOS keeps the phone's voice profile across `launch.yaml` (clearing the keychain is no sign-out), so voice-1/2 run `common/voice-clear-local.yaml` (Me → Remove my voice → confirm) first; Singable persists like the other filters and `discover-reset-filters.yaml` turns it off. Shots in `${VOICE_SHOTS}` = `docs/screenshots/phase3c/<platform>/`; the `voice-tour` / `fit-tour` screen tours go to `docs/screenshots/phase3c/<platform>/<locale>/`. Needs decide with the vocal range fixtures (`DECIDE_DIR` at decide ≥ v0.25).
- **Search stack:** the search service on a fixture song index (:8020; decide `docs/TESTING.md` § Search local stack), part of decide's `scripts/local-stack.sh up` (`search-local-stack.sh` is now a thin wrapper), started from `DECIDE_DIR` (default `../karaoke-decide-phase3-discover` while that branch is unmerged, else `../karaoke-decide`). Both stacks get `DECIDE_GEN_PARTNER_SECRET=local-stack-secret` so decide's `/resolve` reaches gen (the fake judge's global verdict). Fixture songs the flows use: "hello" → Adele, "starlite muse" → Muse "Starlight" (Community + Commercial), "machu picchu strokes" (no karaoke version), "baby" (which one?), "rocket man" (long title).
- **One URL on both platforms:** Android uses `adb reverse tcp:8010` / `tcp:3010` / `tcp:8020` / `tcp:8030`, so the app, fake checkout, the review handoff and the offline-list download all use `http://127.0.0.1`. Metro is started with `EXPO_PUBLIC_GEN_API_URL=http://127.0.0.1:8010 EXPO_PUBLIC_GEN_WEB_URL=http://127.0.0.1:3010 EXPO_PUBLIC_DECIDE_API_URL=http://127.0.0.1:8030 EXPO_PUBLIC_DECIDE_SEARCH_URL=http://127.0.0.1:8020 EXPO_PUBLIC_FAKE_SOCIAL_SIGNIN=1` (inlined at bundle time: restart Metro with `--clear` after changing them). Cleartext http works out of the box (iOS ATS `NSAllowsLocalNetworking`; Android debug manifest `usesCleartextTraffic`).
- **Force offline:** flows tagged `force-offline` (search-4) run last, on a Metro restarted with `EXPO_PUBLIC_SEARCH_FORCE_OFFLINE=1`: search and the song page act as if there were no connection (`useOffline()`), while Me's offline-list download still reaches decide. `config.ts` honours it only against a local decide host.
- **Match judge:** Make it stays disabled until gen's match judge settles (≤ 12 s); `common/make-submit.yaml` waits for it enabled. Every flow's user gets the fake judge's `none`; `stack.js` `ACTION: judge` sets `judge_kind` (`cosmetic`/`content`/`ambiguous`) and the canonical artist/title per user, and `ACTION: job` asserts the user's newest job's artist/title (`TOKEN` = setup's `output.token`).
- **Seeding:** each flow calls `maestro/scripts/stack.js` (`ACTION: setup`) for its own `e2e-<name>-<ms>@example.com` user (`CREDITS`, per-user `USER_CONFIG` knobs) and resets the GLOBAL knobs (search is global) to step delay 0.2 s / `perfect`. `ACTION: code` reads the newest sign-in code from `/api/test/emails`. Per-user fake-config **persists for that email** (a scenario's `fail_at`/`audio_duration_seconds` stick to the user), so never reuse an email across flows.
- **Never run the iOS and Android suites at the same time against one stack.** The search knobs (`search_confidence`, `search_result_count`) and step delay are GLOBAL fake-config: flow 8 sets `unsure` and every flow's setup resets it, so concurrent runs break each other. Run one platform, then the other (or give each its own stack on other ports).
- **Flows 2–10** use "Make any song" (reached through a no-match search's make bar, `common/make-any.yaml`) + the fake Google path; flow 1 and the search flows use the search stack's fixture songs. Screenshots land in `${SHOTS}` = `docs/screenshots/phase1b/<platform>/` (`phase1/` keeps Phase 1's set; paths are relative to the **working directory**, so run Maestro from the repo root).
- **Review flows (review-1…12)** screenshot to `${REVIEW_SHOTS}` = `docs/screenshots/phase2/<platform>/`. Flows tagged `locale-he` (review-9) run as their own group with the app in Hebrew (RTL): `e2e-local.sh` sets the app language before them and resets it after.
- **Screen tours:** `scripts/e2e-local.sh --platform ios --locale he --screen review-tour` runs one `maestro/screens/<name>.yaml` with the app in that language (default `en`), shots in `docs/screenshots/phase2/review/<platform>/<locale>/` (`discover-*` tours: `docs/screenshots/phase3a/<platform>/<locale>/`; `long-title` writes `${SHOTS}/ux-<locale>-*`).

## Rules

1. **Verify on a running app before claiming a UI task is done.** That means a simulator screenshot (`xcrun simctl io booted screenshot <file>` or the Maestro MCP) plus a passing Maestro flow.
2. **No hardcoded user-facing strings.** Use `useTranslations()`. ESLint fails on JSX text literals in `apps/mobile/src` and `packages/ui/src`. Any new key in `packages/i18n/messages/en.json` must be translated (`pnpm i18n:translate`) before commit.
3. **`testID` on every interactive element.** Maestro targets testIDs.
4. **No `@shopify/flash-list` or `@shopify/react-native-skia` imports outside `packages/ui`.** ESLint enforces this. Shopify is winding down both, and a fork or rename must only touch the wrappers.
5. **API clients never touch storage.** The app injects `baseUrl/getToken/getLocale/onUnauthorized` in `apps/mobile/src/api/setup.ts`. Gen owns identity (a 401 signs out). Decide now receives the gen session token (decide validates gen sessions directly, Phase 3a spec §4; no exchange endpoint); Discover's personal data and Tonight's `/api/my/*` karaoke log both use it. A decide 401 never signs the user out: it marks Discover stale (`discover/staleStore.ts`) and Discover shows a refresh prompt; the karaoke-log outbox just waits for the next trigger. Search endpoints stay public.
6. **Gen endpoints with untyped responses** are listed in [docs/gen-untyped-endpoints.md](docs/gen-untyped-endpoints.md). Before calling one, add a zod schema in `packages/api-gen/src/overrides/` and file a gen follow-up to add `response_model`.
7. **Never create Apple, Google Play, Expo/EAS, RevenueCat, Sentry or PostHog accounts, or run anything that costs money, without asking Andrew first.**

## Gotchas (found on device; jest on Node hides them)

- **Voice test: Android's permission dialog sends `AppState` `'background'`** (iOS only goes `'inactive'`). `VoiceTestScreen` cancels on background only while a listening step (`low`, `high`, `sing`) is running, so the first permission prompt doesn't abort `begin()`; blur always cancels.
- **The fake mic is sliced, not streamed.** `assets/fake-mic/baritone-scale.wav` has low / high / sing slices (`scripts/make-fake-mic-wav.mjs` SECTIONS = `FAKE_MIC_SECTIONS`), and each step plays its own slice from the start. A flow must hold long enough after Done enables to reach the slice's extreme (A2 sounds from 3.6 s of the low slice, E4 from 2.0 s of the high slice), or the measured range is too narrow. `FAKE_MIC` is null unless gen is a local host (`config.test.ts`), so a release build can't use it.
- **iOS keeps the phone's voice profile across Maestro's `launch.yaml`** (clearing the keychain is no sign-out and MMKV survives): voice flows start with `common/voice-clear-local.yaml` (Me → Remove my voice; the confirm is anchored below the alert title, because artist rows have "Remove" buttons too).
- **expo-audio's `useAudioStream` releases the native stream in its own unmount cleanup, before ours.** `stream.stop()` afterwards throws `ERR_USING_RELEASED_SHARED_OBJECT`, and a throw in an unmount cleanup closed the release app on leaving the voice screen (found on the prod release APK; the E2E flows use the fake mic, so they never hit it). `useMicPitchSource` swallows that error; the release already stopped capture.
- **iOS: a partial `setAudioModeAsync` resets the fields it leaves out.** `setAudioModeAsync({ allowsRecording: false })` after the mic test put `playsInSilentMode` back to the native default `false` (`.ambient`), so the ringer switch muted review and preview playback for the rest of the launch (`ensurePlaybackAudioMode()` runs once). Always pass the full mode: `useMicPitchSource` stops with `{ ...PLAYBACK_AUDIO_MODE, allowsRecording: false }` (`AFTER_RECORDING_AUDIO_MODE`).
- **Voice test CPU: the mic asks for 16 kHz, and `findHeldNotes` keeps its run median incremental.** The hook reruns `findHeldNotes` over the whole step on every 100 ms buffer; the old per-frame re-sort of the run was O(L² log L) and, at 48 kHz (~94 frames/s), a 20 s hold cost ~290 ms of JS per second of audio. A step has no listening cap (an old 20 s cap dropped the extremes a slide reaches last, seen on a Pixel 9 Pro): `createHeldNoteTracker` (`@nomad/core`) finalises closed segments and old runs of a long gap-free one, so work and memory stay bounded with results identical to `findHeldNotes` over every frame. If a platform ignores the 16 kHz request, the framer adapts to the buffer's real rate (`useVoiceTest.test.ts` runs the whole test at 48 kHz with a per-buffer perf bound).
- **A failing `source.start()` is "mic busy", not a permission problem** (a call, or another app recording): the `mic-busy` step offers Try again (the same step) and the self-report. On `permission-blocked`, coming back to the app (`AppState` `'active'`) asks again, which resolves without a dialog, so allowing the mic in Settings continues the test.
- **Mic comfort is widened around its centre before saving, never to the range edges.** A short free sing gives a narrow comfort band (5–7 keys), which made almost nothing "fit". `profileFromResult` keeps the measured P10–P90 and widens it symmetrically around its centre to `MIN_COMFORT_KEYS` (11 keys), clamped to the range. An earlier rule stretched comfort to `low + 2 … high − 2`, which on a real Pixel turned a measured ~6-key band into 25 keys (comfort ≈ range), so every song "fit"; an offline replay of real singing showed the detector itself is accurate (within 1 semitone of pyin). The voice type still comes from the free-sing centre.
- **decide's voice profile is adopted app-wide** (`useVoiceSync` in AppProviders), not only on Me, or the song page fitted against a stale local profile while the rows' decide badges used the server's.
- **The import upload queue (`discover/connect/importQueue.ts`) is per account and private.** Items, payload files, batches and `lastError` carry the owner (`userKeyFor(email)`, in `auth/userKey.ts`). Signing in as a DIFFERENT account purges the previous owner's queue and payload files (another person's listening history must not stay on the phone); sign-out alone keeps it for the same person and hides the error. Three 401s in a row pause sending until the next sign-in or app foreground (payloads kept); `Retry-After` is floored at 1 s; finished batches are pruned after 24 h.
- **Uploads: SDK 57's global `fetch` is expo/fetch**, which can't send React Native's `{ uri, name, type }` FormData parts ("Unsupported FormDataPart implementation", status 0, nothing reaches the server). Pass an expo-file-system `File` (a Blob with `bytes()`); `@nomad/api-decide`'s upload facades take `UploadFile`.
- **Android 13+ asks for notification permission only once a notification channel exists.** `reminders.ts` creates the channel before requesting permission (SDK 57 docs), or the prompt never shows.
- **`expo-notifications` adds the `aps-environment` (push) entitlement,** which the dev and team signing can't use. `app.config.ts` strips it (`appConfig.test.ts` guards it); local reminders need no push.
- **The import screen (`discover/connect/import-file`) only reads and deletes `file://` copies in `<cache>/DocumentPicker/` (expo-document-picker's `copyToCacheDirectory`) or `<cache>/shared/` (share intake)** (`importFileUri.ts`), and `+native-intent` sends system links whose path is the import-file route to the Connect hub. The real guard is the file allowlist in the route: a sign-in `returnTo` can still reach the screen, and the allowlist refuses anything outside the picker and share-intake cache dirs, so a crafted `?file=` must never read or delete app-private files. Open it only with `router.push` from the picker or share intake.
- **expo-image-picker's `cameraPermission: false` / `microphonePermission: false` block CAMERA / RECORD_AUDIO app-wide** (`tools:node="remove"`, beating expo-camera / expo-audio). Leave them unset; `appConfig.test.ts` guards it. `npx expo config --type introspect` reads an existing `android/` manifest, so check after `npx expo prebuild --clean -p android`.
- **share-intake accepts only other apps' `content://` URIs** (not `file://`, not our own provider) and caps the copy at 256 MiB. The nested `returnTo` in sign-in is double-decoded, so shared file names are sanitised.
- **macOS launchd holds :8021** (a leftover service), so the 3b decide stack uses search on :8022 (`SEARCH_PORT=8022`), API on :8031.
- **Hermes has no `Intl.PluralRules` or `Intl.DisplayNames`.** `installIntlPolyfills()` (`@nomad/i18n`) runs first in `AppProviders` and loads FormatJS plural data for all 33 locales (plus `fil`, because `tl` canonicalizes to it). Language names come from the static `LOCALE_NAMES`. If you use another `Intl` API, check Hermes support or polyfill it.
- **The iOS Keychain (SecureStore) survives uninstall.** The auth store discards a session that has no MMKV install marker, which is wiped on uninstall, so reinstalling the app always starts signed out.
- **Maestro hangs before the first step when adb has no device and something else listens on 127.0.0.1:5560/5561** (e.g. a kjbox `dev_server.py`): Maestro's Android device scan connects to it and waits forever, even for iOS runs. Keep your emulator attached, or start it on another port (`-port 5570`).
- **Maestro on a dev-client build (iOS):** `maestro/common/launch.yaml` uses `stopApp` and `clearKeychain` instead of `clearState` on iOS. `clearState` drops the remembered Metro server, and reconnecting triggers an iOS "Open in …?" SpringBoard prompt that Maestro cannot see. Use the header back button (`tapOn: "Back|Navigate up"`) and avoid `openLink` on iOS for the same reason.
- **Maestro on Android:** `clearKeychain` is a no-op there (the session survives), so `launch.yaml` uses `clearState` on Android, which also forgets the Metro server; it then `openLink`s the dev-client URL `exp+nomad-karaoke://expo-development-client/?url=http%3A%2F%2F10.0.2.2%3A8081` (Metro through 10.0.2.2, no adb reverse). Don't type the URL into the dev launcher: `inputText`/`eraseText` there hung Maestro's driver (120 s gRPC timeout) late in a suite. The header back button is "Navigate up" on Android (`tapOn: "Back|Navigate up"`). A fresh emulator's Chrome shows a first-run screen inside Custom Tabs (`e2e-local.sh` disables it; `common/web-auth-alert.yaml` taps past it). Don't `kill $(lsof -ti tcp:8081)` to restart Metro: the emulator's qemu holds a connection to 8081 and dies with it.
- **Close the in-app browser before `stopApp` on iOS.** Stopping the app with SFSafariViewController (the review handoff) or an auth session (checkout) still open crashes SafariViewService in the simulator (macOS crash dialogs). `maestro/common/close-browser-if-open.yaml` runs before every `stopApp` and as `onFlowComplete` in flows that open a browser (make-1, make-3, review-12); add it to any new one.
- **The dev menu's floating Tools button overlaps the review's header menu** (top right, it takes the ⋯ taps). Review flows run `common/move-dev-tools-button.yaml` before tapping `review-menu`: on Android it drags the button to the left edge (`clearState` resets it every launch); on iOS `e2e-local.sh` turns it off.
- **Maestro on iOS:** `openAuthSessionAsync` (checkout) first shows a "… Wants to Use … to Sign In" alert (`common/web-auth-alert.yaml` taps Continue). The fake checkout's own Cancel needs `rightOf: Pay` (the browser toolbar has a Cancel too). `hideKeyboard` on iOS can tap whatever is under the keyboard; avoid it.
- **Android delivers the checkout return (`nomadkaraoke://checkout?status=…`) to Expo Router too.** `src/app/+native-intent.tsx` keeps the current screen, otherwise "Unmatched Route" covers the credits screen. If the return cold-starts the app (Android killed it during card entry), it opens `/make/new` when a fresh make intent is stored, else Me.
- **Duration confirm sends the full total.** `durationConfirm` (`@nomad/core`) computes `totalCredits` = the job's `state_data.credits_charged` (`?? 1`: jobs made before gen v0.278.2 never recorded it, and gen charged 1) + the pending extra; the app sends that total and gen (≥ v0.278.2) records `credits_charged` on create and resolves the confirm against it.
- **RTL text alignment:** iOS "natural" alignment (RN's `auto`) ignores `I18nManager.forceRTL`, so paragraphs stayed left-aligned in ar/he. `@nomad/ui` `Text` defaults to `textAlign: 'left'`, which RN mirrors to the right under RTL. - **Metro started with `CI=1` doesn't watch files** (`e2e-local.sh` starts it that way): after editing code, restart it, or run your own `npx expo start --dev-client` (same env, no `CI=1`) while iterating.
- **expo-sqlite closes crash (segfault) after an FTS5 query.** Every open of `offline.db` passes `{useNewConnection: true, finalizeUnusedStatementsBeforeClosing: false}` (a typed but `@hidden` option); go through `openOfflineReader()`. `expo-sqlite` is pinned (see the `"//"` key in package.json). The download/unpack itself streams 256 KiB slices (a whole-file read ran Android out of Java heap on the 104 MB .gz).

- **`make.categoryCount` (`"{label} ({count})"`) is hand-written and format-only**, already in `.en-snapshot.json`, so a plain `pnpm i18n:translate` won't redo it (`--no-cache` will).
- **`pnpm i18n:translate` needs `gcloud auth login`** (or, with a lapsed login, `GEMINI_API_KEY=<AI Studio key> pnpm i18n:translate`, which still uses the GCS cache when ADC works; add `--no-cache` via `python3 packages/i18n/scripts/translate.py` if not) (GCS cache + Gemini via ADC) and `env -u GEMINI_API_KEY`.
